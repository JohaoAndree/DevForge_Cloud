# Walkthrough ADR-001: base del proyecto Pulumi

DevForge Cloud ya tiene una base ejecutable en Python para incorporar su infraestructura. La [decisión del ADR-001](../adrs/ADR-001.md#4-decisión) adopta Pulumi para aprovechar el conocimiento de Python y preparar la reutilización mediante `ComponentResource`, delegando al motor IaC la gestión del grafo y del estado. En esta etapa se valida la inicialización del proyecto; las redes y los contenedores corresponden a los ADR posteriores.

[Pulumi.yaml](../../Pulumi.yaml) identifica el proyecto como `devforge-cloud` y configura el runtime Python con el entorno local `venv`. Las dependencias se instalan en ese entorno usando los rangos de [requirements.txt](../../requirements.txt), conforme al paso 1 de la especificación. Esto separa las dependencias del proyecto de las instalaciones globales de Python, aunque los rangos permiten resolver versiones distintas en futuras instalaciones. `components` queda preparado como paquete para alojar las futuras abstracciones de infraestructura.

El flujo actual termina en [__main__.py](../../__main__.py): `build_project_metadata()` obtiene del contexto de Pulumi el proyecto y el stack activos, añade el identificador `pulumi-python` y devuelve los tres valores. Cada llamada construye un diccionario nuevo, según la aclaración del Responsable registrada en el ADR, de modo que modificar un resultado no afecta las llamadas siguientes. Al evaluar el módulo, `pulumi.export("metadata", ...)` publica esos valores como output del stack.

Por ejemplo, con el contexto de pruebas `project="devforge-cloud"` y `stack="test"`, el contrato es:

```python
{"project": "devforge-cloud", "stack": "test", "engine": "pulumi-python"}
```

Las [dos pruebas de inicialización](../../tests/test_project_bootstrap.py) verifican el manifiesto y ese contrato. Los mocks proporcionan el contexto de Pulumi; la segunda prueba también comprueba la llamada de exportación y la independencia de los diccionarios. Su bucle de eventos local permite ejecutar los mocks con Python 3.14. La revisión obtuvo `2 passed` con `venv\Scripts\python -m pytest` y compilación correcta con `venv\Scripts\python -m compileall -q .`. Estas comprobaciones validan la base del programa; la reconciliación de recursos y el aislamiento de red se demostrarán cuando se implemente la infraestructura correspondiente.
